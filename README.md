# 乃木ミー（試作版）

乃木坂46のミーグリ日程・参加メンバー・会話レポートを管理するWebアプリの試作版です。

## 起動方法
`index.html` をブラウザで開いてください。インストールやビルドは不要です。

## 現在できること
- 月間カレンダー表示（下部アイコンナビゲーション）
- 自分の表示名・アプリ背景色の設定
- カレンダーの参加メンバーごとにチケット枚数を登録・変更し、レポートにも枚数を表示
- 42ndシングル発売日（2026/7/22）とミーグリ日程（2026/8/16、9/13、9/27、10/18、10/24、11/15）
- メンバー選択カテゴリ（推し・3期生・4期生・5期生・6期生・OG・全員）
- レポート画像のデザイン選択（乃木坂パープルを初期値）
- シングル発売日・ミーグリ日程の登録、編集、削除
- ミーグリ各部の受付時間・参加時間の編集
- 部ごとの参加メンバー登録（登録すると参加予定として表示）
- 現役・OG区分、公式名はアプリ側で管理する想定。推し登録（推しが一覧の上位に表示）、個別の呼び方（🐟・🏯など）、メンバー別ハート色の設定
- プロフィールの表示名、アプリ背景色の設定
- メンバーごとのレポート背景写真設定（試作版ではブラウザ内に保存）
- LINE風の会話レポート（推しメン左、自分右）
- レポート画像の生成・保存
- X用投稿文とハッシュタグの自動作成
- JSON形式でのデータ書き出し・読み込み

## 重要な制限
- **これは試作版です。** データは開いたブラウザのローカルストレージに保存されます。背景写真を含む大きなデータはブラウザの保存容量を消費します。アカウント・メールアドレス/パスワード認証、クラウド同期、実際のプッシュ通知は未実装です。
- メンバー画面は期別に関係なく五十音順（OGカテゴリは期生順・期内五十音順）。推しを上位表示するのはレポート作成のメンバー選択欄のみ。

現役メンバーは公式メンバー一覧、OGは公開卒業生一覧をもとに登録しています。情報は作成時点の調査に基づくため、最新の卒業状況等は確認が必要です。
- カレンダーの参加メンバーごとにチケット枚数を登録・変更し、レポートにも枚数を表示
- 42ndシングル発売日とオンラインミーグリ6日程を初期登録しています。日程はユーザーが編集・追加できます。
- Xへの画像と文章の一括共有は端末・ブラウザの対応状況に依存します。対応していない場合は画像保存と投稿文の準備を行います。
- 実際に公開する前に、認証、クラウドDB、ユーザーごとのアクセス制御、通知配信、プライバシー・セキュリティの実装が必要です。

### 公開時の注意
PWAとしてホーム画面追加するには、HTTPSで配信し、`index.html`、各 `manifest-*.webmanifest`、`sw.js`、`icons/` を同じサイト上の対応するパスにアップロードする必要があります。ZIPをローカルで開いただけではホーム画面アプリとしてインストールできません。
PWA単体ではiOS/Androidのネイティブホーム画面ウィジェットを作成できません。ウィジェットは後日、ネイティブアプリまたはネイティブの補助アプリが必要です。


## v24: アイコン選択とメールアドレス・パスワードログイン
- ホーム画面アイコンを「自分の画像」「紫背景にレポ文字」「ハート」の3択に変更
- 画像アップロード・プレビューを追加（画像は4MB以下、ブラウザ内の設定に保存）
- メールアドレス＋パスワードのログイン、新規登録、パスワード再設定のUIを追加

- ログアウト時は共有端末で他人のデータが見えないようローカル画面を初期状態に戻す。クラウドのデータはアカウントに残る
- `supabase-config.js` にSupabase Project URLと anon/public keyを設定し、`supabase-schema.sql` をSupabase SQL Editorで実行する必要あり
- Supabase Authのメール確認・パスワード再設定のRedirect URLを本番ドメインに合わせて設定すること

### Supabaseの設定手順
1. Supabaseでプロジェクトを作成する。
2. Project URLと anon/public keyを`supabase-config.js`へ入力する。service_role keyは絶対にフロントエンドへ置かない。
3. SQL Editorで`supabase-schema.sql`を実行する。
4. AuthのSite URLとRedirect URLsを、実際に公開するHTTPSのドメインに設定する。
5. HTTPSで配信し、新規登録・ログイン・ログアウト・別端末ログインで同期をテストする。

### アイコンについて
- 紫背景の「レポ」とハートはPWA用の192px/512pxアイコンを同梱。
- 自分の画像はブラウザ内で保存・プレビューし、iPhoneの`apple-touch-icon`リンクにも反映するよう試みる。AndroidのPWAインストールアイコンはマニフェスト上の画像URLが必要なため、ユーザー別の画像を確実に反映するには画像をサーバーへアップロードして動的なマニフェストを配信する追加実装が必要。
- 既にホーム画面へ追加済みのアイコンはOS側でキャッシュされることがあるため、変更後に削除して再追加が必要な場合がある。
- ログイン前のレポートはローカル保存。ログイン後にクラウド同期される。既存のローカルデータは、クラウドにデータがないアカウントへ最初にログインしたときに初期データとしてアップロードされるので、共有端末では他人のアカウントを使用しないこと。

- アップロード画像は512×512pxに正方形トリミングして保存し、ローカル保存容量を抑えるように変更。

- Project URLとSupabase Publishable keyをsupabase-config.jsへ設定

### 公開前にSupabaseで必ず実行する設定
1. Supabase Dashboard → SQL Editor を開く。
2. このZIPの `supabase-schema.sql` の内容を貼り付けて実行する。
3. Authentication → URL Configuration で、開発中に使うサイトURLとリダイレクトURLを設定する。公開後は本番HTTPS URLも登録する。
4. Authenticationのメール確認設定を確認し、新規登録後に確認メールを受け取れる状態にする。
5. テストアカウントを作成し、登録・メール確認・ログイン・ログアウト・再ログインを試す。

注意: SupabaseのPublishable keyはフロントエンドに置ける公開キーだが、データ保護はRLSポリシーで行う。Secret/service_roleキーはフロントエンドに置かない。
